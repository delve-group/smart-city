# Incident observation content

An incident's subject and description come from the resident's observation, independently of category, issue type and institution. Changing routing does not rewrite content. Address remains a separate field (D083).

Migration 014 recovers the first linked report's summary and observation into private incident fields. It adds nullable `public_content` containing English and Polish title/description pairs. The existing bounded classification completion produces this projection without an additional request; its prompt preserves the specific affected object and uncertainty and removes personal and unit details. Missing public content produces a neutral subject, never a routing-based guess. Private originals remain official-only; public search titles never expose private incident titles.

Public incident and institution DTOs add optional nullable `public_content` for fixture compatibility. Map and staff/institution views display the selected-language stored subject, and details include the description. The approved request includes separate Issue and Description lines. Subsequent linked reports remain evidence and do not automatically overwrite the first report's narrative.

Run `node --conditions=react-server --import tsx scripts/repair-incident-content.ts --all` inside the configured worker to recover legacy incidents, or pass one ticket reference. Recovery does not reclassify or relink reports. It rechecks report and incident versions after completion, supersedes unexecuted approvals through the existing lifecycle and rebuilds proposals where applicable. For open fictional demo tickets, it retains the previous payload/version in the private `service_ticket_content_history`, updates the content/version and audits the correction without sending another request. Closed ticket payloads remain unchanged. Recovery errors are explicit and leave unavailable content unpublished.
